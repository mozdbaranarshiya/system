# سامانه آموزش و پرورش استان اصفهان

سامانه مدیریت مدرسه با رابط فارسی و راست‌به‌چپ، نوشته‌شده با HTML/CSS/JavaScript و مناسب میزبانی رابط کاربری روی GitHub Pages.

## قابلیت‌ها

- مدیر مدرسه: مدیریت معلمان و دانش‌آموزان، پایه، کلاس، درس، عضویت دانش‌آموز در کلاس، تخصیص معلم به کلاس/درس، نماینده کلاس، اطلاعیه گروهی و انفرادی، ثبت نمره، قفل و بازگشایی تکوینی/پایانی.
- معلم: ثبت نمره فقط برای کلاس/درس تخصیص‌یافته، ثبت موقت، ثبت نهایی و قفل تکوینی یا پایانی، مشاهده اطلاعیه‌ها، بررسی اعتراض، تأیید همراه با اصلاح نمره یا رد همراه با علت.
- دانش‌آموز: مشاهده کارنامه، اطلاعیه‌ها، معلم هر درس، ثبت اعتراض برای نمره تکوینی یا پایانی.
- محاسبه خودکار نمره درس: `(تکوینی + پایانی) / 2`.
- نام کاربری هر فرد کد ملی است. در زمان ایجاد کاربر، رمز اولیه نیز همان کد ملی است.
- تغییر مشخصات/رمز حساب‌های معلم و دانش‌آموز فقط از پنل مدیر و Edge Function امن انجام می‌شود.

## چرا دیتابیس داخل GitHub نیست؟

GitHub Pages فقط فایل‌های استاتیک را اجرا می‌کند و پایگاه‌داده، نشست کاربر یا API امن برای نوشتن اطلاعات ندارد. ذخیره نمرات و کد ملی در فایل JSON داخل مخزن باعث افشای اطلاعات و امکان دستکاری داده‌ها می‌شود.

در این پروژه **تعریف دیتابیس** داخل GitHub و در فایل `supabase/schema.sql` نگهداری می‌شود، اما **داده واقعی** در Supabase PostgreSQL ذخیره می‌شود. این روش هم با GitHub Pages سازگار است و هم کنترل دسترسی سمت سرور (RLS) دارد.

## 1) ساخت Supabase

1. وارد https://supabase.com شوید و یک Project جدید بسازید.
2. از منوی **SQL Editor** یک Query جدید باز کنید.
3. محتوای فایل `supabase/schema.sql` را کامل کپی و اجرا کنید.
4. از **Project Settings → API** این دو مقدار را بردارید:
   - Project URL
   - Publishable/anon key
5. فایل `config.js` را باز کنید و مقادیر زیر را جایگزین کنید:
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`

> کلید anon عمومی است. کلید `service_role` را هرگز داخل GitHub یا `config.js` قرار ندهید.

## 2) ساخت اولین مدیر

چون هنوز مدیری در سامانه وجود ندارد، اولین مدیر را یک‌بار از داشبورد Supabase بسازید.

1. در **Authentication → Users → Add user**:
   - Email: `کدملی@school.local`
   - Password: همان کد ملی
   - Auto Confirm User: فعال
2. سپس در **SQL Editor** این دستور را با اطلاعات واقعی اجرا کنید:

```sql
insert into public.profiles (id, national_id, full_name, role)
select id, '0123456789', 'نام مدیر مدرسه', 'manager'
from auth.users
where email = '0123456789@school.local';
```

کد ملی نمونه را با کد ملی واقعی مدیر جایگزین کنید.

## 3) استقرار Edge Function مدیریت کاربران

تابع `supabase/functions/admin-user/index.ts` برای ساخت، ویرایش رمز/کد ملی و حذف امن کاربران است.

### روش CLI

ابتدا Supabase CLI را نصب کنید، سپس:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy admin-user
```

متغیرهای استاندارد `SUPABASE_URL`، `SUPABASE_ANON_KEY` و `SUPABASE_SERVICE_ROLE_KEY` در محیط Supabase Edge Functions استفاده می‌شوند؛ service role نباید در کد فرانت‌اند قرار گیرد.

## 4) ورود

برای همه کاربران:

- نام کاربری: کد ملی
- رمز اولیه: کد ملی

در پشت صحنه، سامانه برای Supabase Auth از آدرس داخلی `کدملی@school.local` استفاده می‌کند؛ کاربر فقط کد ملی را می‌بیند.

## 5) ترتیب راه‌اندازی مدرسه

پس از ورود مدیر:

1. پایه‌ها را ثبت کنید.
2. برای هر پایه، کلاس‌ها و درس‌ها را ثبت کنید.
3. معلم و دانش‌آموز بسازید.
4. دانش‌آموزان را عضو کلاس کنید.
5. معلم را به کلاس و درس مربوط تخصیص دهید.
6. در صورت نیاز نماینده کلاس را تعیین کنید.
7. ثبت نمره و اطلاعیه را شروع کنید.

## 6) منطق ثبت و قفل نمره

### معلم

- **ثبت نمرات**: نمره‌ها موقت ذخیره می‌شوند و تا زمانی که قفل نشده‌اند قابل ویرایش‌اند.
- **ثبت نهایی نمرات**: معلم یکی از «تکوینی» یا «پایانی» را انتخاب می‌کند. همان قسمت قفل می‌شود.
- معلم اجازه بازگشایی قفل را ندارد.

### مدیر

- **ثبت نمرات**: ذخیره موقت.
- **قفل نمرات**: انتخاب «تکوینی»، «پایانی» یا «هر دو».
- **بازگشایی**: مدیر می‌تواند بخش قفل‌شده را دوباره قابل ویرایش کند.

## 7) اعتراض

دانش‌آموز از کارنامه روی «اعتراض» می‌زند و:

- درس به‌صورت خودکار مشخص است.
- تکوینی یا پایانی را انتخاب می‌کند.
- علت را می‌نویسد.

معلم:

- در صورت تأیید، نمره جدید را همان‌جا ثبت می‌کند.
- اگر بخش نمره قفل باشد، مدیر ابتدا باید آن بخش را بازگشایی کند.
- در صورت رد، نوشتن علت رد الزامی است.

## 8) فعال‌کردن GitHub Pages

بعد از Merge شدن تغییرات به شاخه `main`:

1. وارد مخزن GitHub شوید.
2. به **Settings** بروید.
3. از منوی سمت چپ **Pages** را باز کنید.
4. در بخش **Build and deployment**:
   - Source: **Deploy from a branch**
   - Branch: **main**
   - Folder: **/ (root)**
5. روی **Save** بزنید.
6. پس از انجام Deploy، آدرس سایت معمولاً به شکل زیر خواهد بود:

```
https://USERNAME.github.io/system/
```

برای این مخزن، بعد از فعال‌سازی Pages، مسیر مورد انتظار:

```
https://mozdbaranarshiya.github.io/system/
```

- داده‌ها با Row Level Security محدود شده‌اند.
- معلم فقط کلاس/درس تخصیص‌یافته را می‌تواند تغییر دهد.

## احراز هویت دومرحله‌ای مدیر با Ente Auth

حساب‌های دارای نقش `manager` علاوه بر نام کاربری و رمز عبور، باید یک عامل TOTP را تأیید کنند. رابط راه‌اندازی QR Code و کلید دستی را نمایش می‌دهد و با Ente Auth و سایر برنامه‌های استاندارد TOTP سازگار است.

- در اولین ورود مدیر، QR/Secret ساخته می‌شود و مدیر با کد ۶ رقمی اتصال را تأیید می‌کند.
- در ورودهای بعدی مدیر فقط کد ۶ رقمی TOTP درخواست می‌شود.
- معلمان و دانش‌آموزان MFA اجباری ندارند.
- دسترسی‌های مدیریتی در RLS تنها با JWT دارای `aal2` مجاز هستند.
- Edge Function `admin-user` نیز `aal2` را بررسی می‌کند؛ پس بعد از تغییر سورس باید Function دوباره Deploy شود.

برای دیتابیس فایل زیر را اجرا کنید:

`supabase/migrations/20261001_manager_ente_mfa.sql`

### کنترل دسترسی نسخه ۷

تمام جدول‌های جدید RLS دارند. قواعد اصلی:

- مدیر: دسترسی مدیریتی به داده‌های نسخه ۷.
- دبیر: فقط کلاس‌ها، درس‌ها، آزمون‌ها و دانش‌آموزان مرتبط با تخصیص تدریس خودش.
- دانش‌آموز: فقط اطلاعات خودش و مواردی که برای کلاس/پایه/نقش او منتشر شده است.
- پاسخ صحیح بانک سؤال از دسترسی دانش‌آموز جدا شده و آزمون از RPCهای امن استفاده می‌کند.
- رأی ناشناس با Hash غیرقابل استفاده در گزارش عادی ذخیره می‌شود و `user_id` برای رأی ناشناس ذخیره نمی‌شود.
- Audit Log فقط برای مدیر قابل مشاهده است.

2. یک زنگ و برنامه هفتگی بسازید.

4. یک سؤال و آزمون بسازید و آن را منتشر کنید.
5. با دانش‌آموز آزمون را شروع و ثبت نهایی کنید.
6. یک فرم و نظرسنجی ایجاد و با دانش‌آموز ارسال کنید.
7. یک کلاس فوق‌برنامه بسازید و ثبت‌نام دانش‌آموز را آزمایش کنید.
8. یک زمان ملاقات بسازید و از حساب دیگر رزرو کنید.
9. مرکز اعلان و تقویم را بررسی کنید.
10. از بخش گزارش‌ها خروجی Excel بگیرید.
11. در بخش «گزارش فعالیت‌ها» ثبت تغییرات حساس را بررسی کنید.

### نکته درباره زمان و تاریخ

زمان‌ها در PostgreSQL به‌صورت `timestamptz` ذخیره می‌شوند و در رابط با تقویم فارسی نمایش داده می‌شوند. قوانین شروع/پایان آزمون، فرم، نظرسنجی و ثبت‌نام سمت سرور بررسی می‌شوند.
