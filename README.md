# سامانه آموزش و پرورش استان اصفهان — نسخه ۷.۰.۰

سامانه مدیریت مدرسه با HTML، CSS، JavaScript و Supabase، رابط فارسی و RTL، فونت Vazirmatn و میزبانی روی GitHub Pages. اجرای سایت به npm یا مرحله build نیاز ندارد؛ وابستگی‌های npm فقط برای تست توسعه هستند.

نسخه ۷ امکانات نسخه ۶.۱، ثبت و قفل نمره، اعتراض، انضباط نماینده کلاس، گروه‌ها و بایگانی امتیازها، ارسال و اصلاح تکلیف، دفتر نمرات تکالیف، ورود Excel و MFA مدیر را نگه می‌دارد. `schema.sql` و Migrationهای قبلی تغییر نکرده‌اند. ارتقا با چهار Migration جدید انجام می‌شود.

## ارتقای Supabase موجود

این مسیر برای دیتابیس نسخه ۶.۱ با Migration احراز هویت مدیر است. پیش از ارتقا، یک نسخه پشتیبان بگیرید. روی دیتابیس موجود، `schema.sql` را دوباره اجرا نکنید؛ آن فایل برای راه‌اندازی اولیه نسخه پایه است.

چهار فایل زیر را **یک‌بار و به همین ترتیب** در Supabase SQL Editor با نقش `postgres` اجرا کنید. هر فایل تراکنش مستقل دارد؛ در صورت خطا همان مرحله را بررسی کنید و به فایل بعدی نروید.

| ترتیب | فایل | محتوا |
| --- | --- | --- |
| ۱ | `supabase/migrations/20261002_system_v7_01_core.sql` | حساب آماده، حفاظت رمز، کنترل دسترسی قبلی، Audit، زنگ، برنامه، حضور، رفتار و تنظیمات |
| ۲ | `supabase/migrations/20261002_system_v7_02_exams.sql` | بانک سؤال، snapshot آزمون، پاسخ صحیح خصوصی، تلاش و تصحیح |
| ۳ | `supabase/migrations/20261002_system_v7_03_community.sql` | تقویم، فرم، نظرسنجی، فوق‌برنامه، ملاقات و RPCهای تراکنشی |
| ۴ | `supabase/migrations/20261002_system_v7_04_integrations.sql` | اعلان، یادآوری، تقویم و داشبورد تجمیعی، پرونده، bootstrap، Search و گزارش |

هیچ جدول قدیمی یا رکورد موجودی حذف یا بازسازی نمی‌شود. مقادیر پیش‌فرض تنظیمات: حد نصاب قبولی ۱۰، آستانه غیبت زیاد ۵ و نام مدرسه «سامانه مدرسه». مدیر می‌تواند آن‌ها را در تنظیمات تغییر دهد. تا پیش از تغییر نام مدرسه، نام `config.js` استفاده می‌شود.

این مسیر جایگزین Migrationهای پیش‌نویس قبلی نسخه ۷ است؛ فایل‌های `20261002_system_v7.sql` یا `20261002_system_v7_01_security.sql` را همراه این چهار فایل اجرا نکنید. این ارتقا بر پایه schema نسخه ۶.۱ نوشته شده است.

رمز حساب‌های موجود عوض نمی‌شود. تنها حساب‌هایی که hash رمز آن‌ها هنوز با کد ملی برابر است، `must_change_password=true` می‌گیرند؛ حساب‌های جدید و رمزهایی که مدیر بازنشانی می‌کند نیز این پرچم را دارند. حساب مدیر ابتدا MFA و سپس تغییر رمز اولیه را تکمیل می‌کند.

پس از چهار Migration، `supabase/migrations/20261009_manager_session_guard.sql` را برای کنترل Session و عامل MFA جاری مدیر اجرا کنید؛ سپس **هر دو Edge Function را مستقر کنید** و فایل‌های رابط نسخه ۷ را منتشر کنید. رابط جدید پیش از اجرای Migrationها قابل استفاده کامل نیست. افزودن OAuth به Migration جداگانهٔ بخش اتصال ChatGPT نیاز دارد.

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy admin-user --no-verify-jwt
supabase functions deploy account-security --no-verify-jwt
```

هر دو تابع JWT دقیق را از Supabase Auth معتبر می‌کنند؛ تنظیم gateway در `supabase/config.toml` با کلید Publishable جدید سازگار است. `admin-user` ساخت و مدیریت کاربران را فقط برای مدیر فعال با AAL2، عامل TOTP جاری و رمز تغییرکرده انجام می‌دهد. `account-security` JWT و رمز فعلی را بررسی می‌کند، فقط رمز همان حساب را تغییر می‌دهد و پرچم اولیه را سمت سرور برمی‌دارد؛ مدیر ابتدا باید Session/MFA جاری معتبر داشته باشد. رمز جدید حداقل ۸ کاراکتر، متفاوت از رمز فعلی و کد ملی است.

این توابع از متغیرهای محیطی Supabase استفاده می‌کنند: `SUPABASE_URL`، `SUPABASE_ANON_KEY` و `SUPABASE_SERVICE_ROLE_KEY`؛ تنظیم کلیدهای جدید `SUPABASE_PUBLISHABLE_KEYS` و `SUPABASE_SECRET_KEYS` نیز پشتیبانی می‌شود. کلید سرویس فقط در Edge Function است و نباید در `config.js` یا مخزن قرار گیرد.

## راه‌اندازی پروژه جدید

اگر پروژهٔ مقصد از قبل برنامه یا جدول‌های دیگری دارد، مسیر [نصب مستقل مدرسه در پروژهٔ مشترک](docs/MIGRATION.md) را استفاده کنید. نصب مستقیم جدول‌های مدرسه در `public` چنین پروژه‌ای می‌تواند با جدول‌های موجود تداخل داشته باشد.

1. یک پروژه Supabase بسازید و `supabase/schema.sql` را اجرا کنید؛ این فایل پایه شامل امکانات تا نسخه ۶.۱ و MFA است.
2. چهار Migration نسخه ۷ و سپس Migration کنترل Session مدیر `20261009_manager_session_guard.sql` را طبق توضیح بالا اجرا کنید. Migrationهای قبلی را بعد از آن دوباره اجرا نکنید.
3. `SUPABASE_URL`، `SUPABASE_ANON_KEY` عمومی و `SCHOOL_NAME` را در `config.js` تنظیم کنید.
4. هر دو Edge Function را مستقر کنید.
5. در Authentication → Users یک مدیر با ایمیل `کدملی@school.local` و رمز اولیه بسازید و Auto Confirm را فعال کنید. سپس با UUID واقعی حساب، پروفایل را ایجاد کنید:

```sql
insert into public.profiles(id,national_id,full_name,role,must_change_password)
values('UUID_FROM_AUTH_USERS','0123456789','نام مدیر مدرسه','manager',true);
```

6. وارد شوید، TOTP را با Ente Auth یا برنامه سازگار تنظیم کنید و رمز اولیه را تغییر دهید.
7. پایه، کلاس، درس، کاربران، عضویت دانش‌آموز و تخصیص دبیر را ثبت کنید؛ سپس زنگ و برنامه هفتگی را بسازید.

برای پروژه قدیمی‌تر از ۶.۱، ابتدا ارتقای همان نسخه‌های قبلی را انجام دهید: `20261001_education_v2.sql`، اصلاح `20261001_fix_groups_homework_rls.sql`، سپس `20261001_system_v6.sql`، `20261001_system_v6_1_0.sql` و `20261001_manager_ente_mfa.sql`. فایل‌های `20261001_fix_api_privileges.sql` و `20261001_fix_service_role_profiles.sql` برای اصلاح مجوزهای نصب‌های قدیمی موجودند.

## زمان‌بندی یادآوری‌ها

اعلان‌های ناشی از ثبت یا تغییر اطلاعات با Trigger ساخته می‌شوند. یادآوری مهلت تکلیف و آغاز آزمون در ۲۴ ساعت آینده، اعلان نتیجه پس از پایان کلی آزمون و نهایی‌کردن تلاش‌های منقضی‌شده، به اجرای دوره‌ای `generate_school_reminders()` نیاز دارند.

اگر `pg_cron` پیش از Migration چهارم فعال باشد، برنامه ۱۵ دقیقه‌ای خودکار ساخته می‌شود. در غیر این صورت، افزونه را در Supabase فعال کنید و این دستور را یک‌بار در SQL Editor اجرا کنید:

```sql
select cron.schedule(
  'system-v7-reminders',
  '*/15 * * * *',
  'select public.generate_school_reminders()'
);
```

برای بررسی برنامه و اجرای دستی توسط مالک دیتابیس:

```sql
select jobid,jobname,schedule,active
from cron.job where jobname='system-v7-reminders';
select public.generate_school_reminders();
```

کاربران مرورگر اجازه اجرای این RPC را ندارند. اجرای تکراری اعلان یکسان ایجاد نمی‌کند. هر اجرا حداکثر ۵۰۰ تلاش منقضی‌شده را نهایی می‌کند. پایان آزمون در رابط نیز پاسخ‌های دریافت‌شده را ارسال می‌کند؛ کنترل پذیرش پاسخ همیشه در سرور است.

## نقش‌ها و RLS

| نقش | دسترسی |
| --- | --- |
| مدیر | مدیریت مدرسه و اطلاعات، گزارش و پرونده همه دانش‌آموزان، Audit؛ فقط با MFA سطح AAL2 |
| دبیر | نمره، حضور و رفتار در کلاس/درس تخصیص‌یافته؛ بانک سؤال و آزمون خود؛ فوق‌برنامه و ملاقات تحت مسئولیت خود؛ سایر محتوای مخاطب‌دار مجاز |
| دانش‌آموز | اطلاعات و پرونده خودش، برنامه کلاس، آزمون و تکلیف مجاز، فرم/نظرسنجی مخاطب خود، ثبت‌نام فوق‌برنامه و رزرو ملاقات |
| نماینده/سرگروه | همان دسترسی قبلی انضباط یا امتیاز گروه مربوط، در کنار نقش دانش‌آموز |

هر ۲۷ جدول جدید RLS دارند. حساب غیرفعال، رمز اولیه تغییرنکرده و مدیر بدون AAL2 از دسترسی عادی در خود دیتابیس منع می‌شوند. پرونده، تقویم، Search و گزارش زیر RLS اجرا می‌شوند؛ مخفی‌کردن دکمه، کنترل امنیتی اصلی نیست.

پاسخ صحیح آزمون مجوز خواندن مستقیم برای `authenticated` ندارد. پاسخ و نمره دانش‌آموز از RPC با حذف اطلاعات زودهنگام ارائه می‌شود. رأی‌های نظرسنجی از جدول مستقیم خواندنی یا نوشتنی نیستند؛ RPC فقط مجموع و درصد را برای نظرسنجی ناشناس برمی‌گرداند. مدیر نیز هویت رأی‌دهندگان ناشناس را دریافت نمی‌کند. مشخصات لازم هم‌کلاسی‌ها برای گروه‌های قدیمی با نام و بدون کد ملی در bootstrap باقی می‌ماند.

Audit با Trigger و شناسه حساب احرازشده ساخته می‌شود؛ کاربران مرورگر، از جمله مدیر، اجازه درج، ویرایش یا حذف Audit ندارند. مدیر فقط آن را می‌خواند. تغییر پروفایل در Edge Function با RPC مخصوص service role، شناسه caller تأییدشده را به‌صورت تراکنشی در Audit ثبت می‌کند؛ مرورگر اجازه اجرای این RPC را ندارد. فایل‌های تکلیف همچنان در Bucket خصوصی `assignment-files` با محدودیت دسترسی نسخه قبل و شرط آمادگی حساب هستند.

«خروج از همه دستگاه‌ها» نشست‌های قابل تمدید را لغو می‌کند؛ اعتبار access token صادرشده تا انقضای آن تابع سیاست Auth است.

## راهنمای کار با بخش‌ها

### نمره و کارنامه

فرمول درس همان `(تکوینی + پایانی) / 2` است. نمره سالانه میانگین نهایی دو نوبت است؛ نمره ناقص صفر فرض نمی‌شود و صفر ثبت‌شده در محاسبه می‌ماند. معدل از نمرات موجود محاسبه می‌شود و تا تکمیل تمام دروس، وضعیت کلی «نمره ناقص» است. نمرات سال‌ها و کلاس‌های متفاوت با هم مخلوط نمی‌شوند. قفل تکوینی/پایانی، بازگشایی توسط مدیر، کلید نمایش کارنامه و اعتراض نسخه قبل حفظ شده‌اند.

### حضور و برنامه

مدیر زنگ‌ها و تخصیص‌های کلاس/درس/دبیر را تعریف می‌کند. تداخل زنگ‌ها، تکرار برنامه کلاس و برنامه هم‌زمان دبیر سمت سرور رد می‌شود. در حضور، کلاس، درس، تاریخ شمسی و جلسه انتخاب می‌شوند؛ فهرست ابتدا حاضر است و ذخیره گروهی اتمی انجام می‌شود. ثبت مجدد همان جلسه، رکورد را اصلاح می‌کند. گزارش‌ها بازه روز/هفته/ماه/سال و تفکیک وضعیت دارند.

### آزمون

دبیر سؤال‌ها را در بانک می‌سازد و برای هر آزمون بارم، کلاس/درس، زمان شروع و پایان و مدت را تعیین می‌کند. مجموع بارم کنترل و متن، گزینه‌ها و پاسخ صحیح snapshot می‌شوند. پس از شروع یک تلاش، سؤال‌ها و مشخصات آزمون قابل تغییر نیستند؛ کلید نمایش نتیجه همچنان قابل مدیریت است.

هر دانش‌آموز یک تلاش دارد. مهلت برابر کوچک‌ترِ پایان آزمون و زمان شروع تلاش به‌علاوه مدت است. تایمر با زمان سرور آغاز می‌شود و پاسخ تشریحی با debounce و پاسخ گزینه‌ای بلافاصله ذخیره می‌شود. درخواست‌های یک سؤال به ترتیب ارسال می‌شوند؛ ارسال دستی ابتدا ذخیره‌های در حال انجام را کامل می‌کند. پاسخ تازه پس از مهلت پذیرفته نمی‌شود، ولی ارسال نهایی پاسخ‌های قبلاً ذخیره‌شده مجاز است.

چهارگزینه‌ای و صحیح/غلط خودکار تصحیح می‌شوند؛ پاسخ کوتاه و تشریحی به دبیر نیاز دارند. نمره نهایی تا تصحیح همه پاسخ‌ها ناقص است. حتی با فعال‌بودن نمایش نتیجه، دانش‌آموز پیش از **پایان کلی پنجره آزمون** نمره، بازخورد تصحیح یا کلید صحیح دریافت نمی‌کند.

### تقویم، فرم و نظرسنجی

تاریخ‌ها در دیتابیس استاندارد و زمان‌ها با منطقه تهران تفسیر می‌شوند؛ نمایش و ورودی UI شمسی است. تقویم ماهانه دسکتاپ و فهرست موبایل محتوای دستی و خودکار مجاز را کنار هم نمایش می‌دهند.

فرم‌ساز متن کوتاه/بلند، عدد، تاریخ، ساعت، انتخاب تکی/چندگانه و بله/خیر دارد. مدیر ترتیب و مهلت، مخاطب و پاسخ چندباره را تعیین می‌کند؛ سرور نوع پاسخ، فیلد الزامی، گزینه‌ها، مهلت و تعداد ارسال را اعتبارسنجی می‌کند. نتایج و خروجی کامل از صفحه فرم در دسترس‌اند.

برای نظرسنجی هر حساب یک رأی دارد. پس از رأی، مشخصات و گزینه‌ها قفل می‌شوند تا نتیجه و ناشناسی تغییر نکند؛ کلید نمایش نتیجه قابل تغییر است.

### فوق‌برنامه، ملاقات و جست‌وجو

درخواست‌های در انتظار و تأییدشده فوق‌برنامه جای ظرفیت را می‌گیرند؛ لغو یا رد آن را آزاد می‌کند. مدیر یا دبیر مسئول جلسات و وضعیت اعضا را مدیریت می‌کند. رزرو ملاقات نیز ظرفیت و تداخل مسئول و درخواست‌کننده را تحت قفل تراکنشی بررسی می‌کند؛ تأیید آن به تقویم و اعلان می‌رود.

جست‌وجوی Header از دو حرف آغاز می‌شود، نتایج را دسته‌بندی می‌کند و فقط اطلاعاتی را می‌یابد که حساب طبق RLS اجازه مشاهده دارد.

### گزارش، چاپ و آیکون

گزارش‌ها و فهرست‌های اصلی صفحه‌بندی دارند. Export تمام صفحات مجاز را جمع می‌کند؛ برگه Excel RTL است و کد ملی رشته باقی می‌ماند. «چاپ / PDF» جدول کامل فیلترشده را با فونت فارسی، نام مدرسه، تاریخ و فیلتر آماده می‌کند؛ در پنجره چاپ مرورگر A4 و Save as PDF را انتخاب کنید. این مسیر به سرویس تولید PDF روی سرور نیاز ندارد.

پرونده، برای جلوگیری از پاسخ بسیار بزرگ، آخرین ۲۰۰ مورد هر بخش را نمایش می‌دهد؛ برای سوابق بیشتر از گزارش کامل استفاده کنید. زنگ اعلان هر ۶۰ ثانیه تازه می‌شود.

نشان اصلی در `assets/icons/logo.svg` است. PNGهای ۱۶، ۳۲، ۱۸۰، ۱۹۲ و ۵۱۲ و ICO در همان پوشه‌اند. Manifest فارسی و RTL، `start_url` و `scope` نسبی دارد و زیرمسیر `/system/` را پشتیبانی می‌کند. نصب‌پذیری روی دستگاه تابع پشتیبانی مرورگر است؛ برنامه اتصال زنده به Supabase دارد و حالت آفلاین پیاده نشده است.

## اتصال حساب به ChatGPT

افزونهٔ OAuth از Login و MFA موجود استفاده می‌کند و فقط داده‌های مجاز حساب را با scopeهای محدود و توکن‌های قابل لغو در اختیار Client می‌گذارد. رمز کاربر و TOTP به ChatGPT ارسال نمی‌شود. راهنمای معماری، migration افزایشی، تنظیمات سرور، ثبت callback دقیق، چرخهٔ توکن و استقرار در [docs/OAUTH.md](docs/OAUTH.md) و schema خواندن API در [docs/chatgpt-openapi.yaml](docs/chatgpt-openapi.yaml) قرار دارند.

برای افزودن OAuth به دیتابیس نسخهٔ ۷، `supabase/migrations/20261007_oauth_connector.sql` بعد از چهار Migration قبلی لازم است؛ `20261009_manager_session_guard.sql` نیز کنترل MFA جاری مسیرهای مدیریتی را اضافه می‌کند. هر سه تابع با تنظیم gateway ذکرشده در مستندات مستقر شوند. در پروژهٔ مشترکِ دارای برنامهٔ آزمون، نصب‌کنندهٔ مستقل [docs/MIGRATION.md](docs/MIGRATION.md) جایگزین اجرای مستقیم این فایل‌ها روی `public` است. تنظیم سرور `SYSTEM_DB_SCHEMA=school` و تنظیم عمومی سایت `SUPABASE_DB_SCHEMA: "school"` و `ASSIGNMENT_BUCKET: "school-assignment-files"` برای آن مقصد لازم‌اند. اجرا و تست محلی، جایگزین انتقال داده، استقرار و تنظیم Client واقعی با callback دقیق GPT Builder نیست.

تست‌های اختصاصی: `npm run test:oauth`. تست Auth واقعی اختیاری با `npm run test:auth:live` و تست رقابت PostgreSQL با `npm run test:oauth:concurrency` روی سرویس آزمایشی Docker محلی اجرا می‌شوند و به داده یا کلید Supabase تولید دست نمی‌زنند. تست Consent در مرورگر با `npm run test:oauth:browser` اجرا می‌شود.

## توسعه و تست

Node.js نسخه ۲۴ و npm برای تست کافی است:

```bash
npm ci
npm run check
npm test
npm run test:xlsx
```

- `check`: بررسی syntax تمام فایل‌های JavaScript و هر سه Edge Function.
- تست دیتابیس: اجرای schema قدیمی و چهار Migration روی PostgreSQL آزمایشی PGlite، سپس ۶۳ تست حفظ اطلاعات و RLS/RPC، زمان آزمون، تصحیح، رأی ناشناس، ظرفیت، تداخل، اعلان و سازگاری گروه/تکلیف قدیمی.
- تست واحد: تبدیل شمسی و سال کبیسه، صفر و نمره ناقص، اندازه آیکون و مسیر Manifest.
- تست امنیت حساب و مدیریت کاربران: ۲۲ و ۳۲ بررسی مرز درخواست، Session/MFA معتبر و عضویت مدرسه با Auth/SDK جایگزین؛ این تست‌ها استقرار واقعی Supabase Auth را جایگزین نمی‌کنند.
- تست نصب مستقل: ۴۰ بررسی PostgreSQL آزمایشی برای حفظ برنامهٔ موجود، RLS و Storage، کنترل کاربران مشترک و MFA مدیر؛ دستور مستقل `npm run test:schema` است.
- تست OAuth: ۲۲۱ بررسی DB، HTTP، Handler→SQL و UI؛ تست‌های تکمیلی GoTrue واقعی و رقابت PostgreSQL جداگانه اجرا می‌شوند.
- تست صفحات: ۷۳ بررسی DOM با دیتابیس واقعی آزمایشی برای سه نقش، تغییر رمز اجباری، فرم و ذخیره پاسخ تشریحی بدون blur.
- `test:xlsx`: دریافت SheetJS ثابت ۰.۲۰.۳ از jsDelivr با SHA-256 تطبیق‌یافته با منبع رسمی، بررسی اصالت cache و ساخت و بازخوانی `.xlsx` واقعی؛ RTL، فارسی، نوع عدد و صفر ابتدای کد ملی بررسی می‌شوند. فایل آزمایش در `test-results/` قرار می‌گیرد.

تست‌ها به پروژه Supabase زنده، کاربران واقعی یا service role نیاز ندارند و تغییری در آن‌ها نمی‌دهند.

تست مرورگر واقعی، موبایل، تصاویر و PDF:

```bash
npx playwright install --with-deps chromium
npm run test:browser
```

این تست از همان دیتابیس آزمایشی و SDK جایگزین استفاده می‌کند و درخواست به Supabase زنده را مسدود می‌کند. تصاویر دسکتاپ/موبایل، PDF و Excel را در `test-results/` می‌سازد. در محیط ابری، اجرای Chromium سیستم با `CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` موفق شد: ۵۶ بررسی صفحات، موبایل و خروجی‌ها پاس شدند. این نتیجه تأیید ورود به پروژهٔ تولید یا اتصال Client واقعی ChatGPT نیست؛ آزمون استقرار و callback واقعی پیش از انتشار عمومی لازم است.
